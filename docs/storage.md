# Файлы во Flash ESP32 · Firmware 0.3 / Control Center 0.4

На странице **«Файлы»** отображается содержимое самой платы. ESP32 выполняет чтение, запись, создание папок, копирование, переименование и удаление; Windows-приложение передаёт команды и предоставляет редактор. После завершённого сохранения компьютер для хранения данных не нужен. Файлы не являются исполняемыми программами: интерпретатор сценариев пока не реализован.

## Повседневная работа

Подключите плату к USB-UART, запустите `MikuOS.lnk` и откройте «Файлы».

- Двойной щелчок открывает папку или текстовый файл. Поле поиска фильтрует текущую папку. Путь можно ввести вручную; «Выше» возвращает в родительскую папку.
- «Новая папка» и «Новый текст» создают объекты на ESP32. Текст редактируется справа; «Сохранить на ESP32» или Ctrl+S передаёт изменённый файл на плату.
- «Загрузить с ПК» принимает любые байты: текст, изображения, документы и другие форматы. «Скачать на ПК» проверяет CRC32 и записывает полученную копию после успешной передачи.
- «Переименовать», «Копировать» и «Удалить» выполняются на устройстве. Копирование не скачивает исходник на ПК: ESP32 создаёт фоновую задачу, приложение показывает её прогресс и может отменить её. Папка удаляется только после освобождения её содержимого.
- «Копия текста на ПК» сохраняет текущий буфер редактора, включая несохранённые правки. Эта кнопка доступна и после потери подключения.
- При замене существующего файла и удалении приложение показывает конкретный объект. При открытии другого текста или закрытии приложения предлагает сохранить несохранённые правки.

Редактор поддерживает строгий UTF-8, сохраняет BOM при его наличии и выбранный по исходнику стиль переноса строк (LF, CRLF или CR). Файл со смешанными переносами при сохранении нормализуется к обнаруженному стилю. Двоичные данные и текст другой кодировки доступны через скачивание. Текстовый редактор ограничен 256 КиБ; общий размер одного файла — 4 МиБ.

## Раздел и ограничения

| Параметр | Значение |
|---|---|
| Носитель | Встроенная 16 МиБ Flash ESP32-S3 N16R8 |
| Раздел `storage` | `data,fat`, offset `0x410000`, size `0xBF0000` (11,9375 МиБ) |
| Файловая система | FATFS с wear levelling, два FAT, сектор 4096 байт |
| Рабочий mount | `/data`; пользовательские пути начинаются с `/` |
| Свободное место | Реальные значения FATFS; часть раздела занимает служебная информация |
| Размер файла | До 4 МиБ; для замены нужна свободная временная копия плюс резерв 64 КиБ |
| Каталог | До 128 элементов; выдача страницами по 8 |
| Путь | До 160 байт UTF-8, отдельное имя до 128 байт; русские буквы и пробелы разрешены |
| Передача | Блоки до 2048 байт, один активный upload, простой 30 секунд завершает upload |
| Служебная папка | `/.miku` закрыта для пользовательских операций |

Пути с `..`, `.`, пустыми сегментами, управляющими символами и запрещёнными FAT-символами отклоняются. Корень нельзя удалять или переименовывать. Переименование не заменяет существующий объект. На FAT регистр имени не создаёт отдельный файл.

## Сохранение и восстановление

1. Клиент передаёт размер и CRC32, плата создаёт `/.miku/upload.bin`.
2. Каждый блок имеет строго ожидаемое смещение. Исходный файл не изменяется во время передачи.
3. `commit` проверяет полноту и CRC32. Ошибка или отмена удаляет только временную копию.
4. Перед заменой записывается журнал с целевым путём; прежняя версия переименовывается в `/.miku/old.bin`. Затем временная копия становится целевой, служебные файлы удаляются.
5. После запуска незавершённая замена восстанавливает старый файл, если целевой отсутствует; если целевой уже присутствует, освобождает резервную копию. Недопустимый журнал или неожиданный backup запрещают дальнейшие изменения и сохраняют данные для диагностики.

Версия хранилища состоит из случайного идентификатора запуска и счётчика изменений. Чтение несколькими блоками и страницами каталога требует одной версии; редактор передаёт версию открытого файла при сохранении. Изменение хранилища или перезапуск исключают молчаливую запись устаревшего буфера. После собственных операций UI обновляет версию открытого текста только после повторной проверки его размера и CRC32.

Это защита на уровне приложения, а не гарантия транзакционности всей FAT при произвольном пропадании питания. Восстановление этапов замены проверяется на host; физическое отключение питания в процессе изменения FAT ещё требует отдельных экспериментов. Операции записи вызывают flush/fsync. Фоновая задача копирования переносит и проверяет один блок за проход worker; между блоками выполняются обычные сервисы и команды. Если клиент закрывает порт, ESP32 продолжает копирование при наличии питания. CRC большого файла вычисляется блоками со сбросом watchdog, уступкой FreeRTOS и HB; во время этой команды периодические сервисы MikuOS могут задерживаться. Активные передачи нельзя автоматически повторять после разрыва: сначала перечитайте актуальное состояние.

## Прошивка без потери файлов

Первая установка на новую плату:

```powershell
./scripts/build-firmware.ps1
./scripts/flash-firmware.ps1 -Port COM5 -InitializeStorage
```

Скрипт сначала сохраняет **все 16 МиБ Flash** в `backups`, проверяет размер образа и layout. `-InitializeStorage` устанавливает подготовленный FATFS-образ с README и папкой docs. Если в backup обнаружен FAT-том, инициализация прекращается. Ошибка mount в самой прошивке **не запускает форматирование**.

Обычное обновление:

```powershell
./scripts/flash-firmware.ps1 -Port COM5
```

`storage.bin` намеренно отсутствует в стандартных `flash_args`: обновляются bootloader, таблица разделов и программа, пользовательские файлы остаются на месте. Полное восстановление старого backup вернёт также старые данные. Резервные копии не публикуются в Git.

## Терминал

```text
df
ls /
mkdir /notes
write "/notes/Моя заметка.txt" "Привет, Miku!"
cat "/notes/Моя заметка.txt"
cp "/notes/Моя заметка.txt" /notes/copy.txt
mv /notes/copy.txt /notes/renamed.txt
touch /notes/empty.txt
rm /notes/renamed.txt
```

`cat` выводит текст до 3072 байт. Для более крупных файлов и бинарных данных используйте страницу «Файлы». Пути с пробелами заключаются в кавычки.

## Проверки

`.NET` проверяет клиент через намеренно фрагментированный simulator transport: двоичный round trip, многостраничные каталоги, редактирование, конфликт версий, отмену, reconnect/reboot, timeout и disconnect. C++ тесты проверяют CRC, восстановление прерванной замены и истечение upload. Общий интеграционный сценарий использует настоящий C++ host или прошитую плату:

```powershell
py -3.11 tests/storage_integration.py --host firmware/build/Release/miku-host.exe
./.tools/python/Scripts/python.exe tests/storage_integration.py --port COM5
```

Он создаёт отдельную папку `test-<случайный ID>`, проверяет текст/бинарные данные, границы блоков, ошибки CRC, защиту путей, папки, copy/rename, reboot и удаляет свою папку при успешном завершении. При прерывании тестовая папка может остаться; чужие файлы не удаляются. Аппаратный режим требует pyserial. Детали фактических прогонов — в [hardware-testing.md](hardware-testing.md).

Демонстрационный том сохраняется в памяти Windows-процесса при reconnect/reboot, но исчезает при закрытии приложения. C++ host сохраняет файлы в обычной папке и принимает `--storage-root <directory>`. На реальном Serial эти локальные хранилища не используются.

Настройки и API проверены по исходникам ESP-IDF 5.5.2 и [официальному описанию FATFS](https://docs.espressif.com/projects/esp-idf/en/v5.5.2/esp32s3/api-reference/storage/fatfs.html).
