# MikuOS как курсовой проект

Предлагаемая тема: «Разработка программируемого контроллера MikuOS на ESP32-S3 с автономным исполнением сценариев и графическим интерфейсом Windows Forms».

Цель — создавать на ПК сценарии работы устройства, передавать их через USB/Serial и исполнять на микроконтроллере. ESP32 хранит сценарии и настройки, планирует выполнение, обращается к аппаратным интерфейсам и записывает результаты. Windows-приложение служит средством программирования, управления и наблюдения. После закрытия приложения сценарии продолжают работать при наличии питания.

## Что следует из методички

Источник — предоставленные методические указания «Программирование интерфейсов вычислительных систем», ДОННТУ, 2022. В разделе с примером требуется интерфейс на C#, USB-обмен с Arduino и отображение показаний подключённых датчиков. Пример решения управляет светодиодом и сервоприводом. Индивидуальные варианты выдаются отдельно; пользователь сообщил, что фиксированного варианта нет и ESP32 разрешена вместо Arduino.

Полноценная операционная система общего назначения в методичке не требуется. Собственный системный слой MikuOS и исполнитель сценариев — выбранное расширение проекта, которое должно подкрепляться реальной аппаратной функцией и экспериментами.

## Содержательная особенность проекта

Пользователь передаёт новый сценарий без перепрошивки. Исполнитель на ESP32 выполняет ограниченный набор инструкций, уступает управление при ожидании и сохраняет работоспособность системных сервисов. Несколько сценариев имеют независимые состояния, счётчики выполнения и ограниченные ресурсы. Ошибка сценария отражается в журнале и его состоянии.

Это учебная среда исполнения поверх ESP-IDF/FreeRTOS. Нельзя заявлять полноценную ОС общего назначения, запуск произвольных исполняемых файлов, аппаратную изоляцию памяти или измеренную загрузку CPU без соответствующей реализации и проверки.

## Демонстрация для защиты

1. Запустить плату и подключиться из Control Center, показать реальный обмен и состояние системы.
2. Создать и сохранить сценарий на ESP32, запустить его и наблюдать выполнение на устройстве.
3. Запустить второй сценарий, показать ожидание и совместную работу задач.
4. Закрыть Windows-приложение, оставить питание и подтвердить продолжение работы по накопленным результатам и аппаратному выходу.
5. Перезапустить ESP32 и подтвердить сохранение файлов и автоматический запуск выбранного сценария.
6. Запустить ошибочный сценарий и показать локализацию ошибки и продолжение работы системы.

Конкретные датчики, выходы и экран выбираются после уточнения доступного оборудования. Работу без ПК нельзя подтверждать одним лишь ростом uptime: нужны результаты автономной задачи либо наблюдаемое аппаратное действие.
