# Архитектура и границы первой итерации

`shared/MikuOS.Core` — независимая от UI библиотека .NET: Frame/FrameDecoder, ITransport, SimulatedDevice, SimulatorTransport. Симулятор всегда проходит через сериализацию и stream decoder, в том числе при подключении внутри процесса.

`control-center` — Windows Forms. UI получает кадры через ITransport, переносит обработку на UI thread, сопоставляет RES/ERR по ID, хранит таймауты. SerialTransport изолирует System.IO.Ports; TCP можно добавить новой реализацией ITransport. Callback старого подключения игнорируется после переключения. Dashboard, Terminal и график выделены в отдельные контролы. MainWindow выполняет композицию и маршрутизацию.

`firmware/kernel` — собственный кооперативный системный слой поверх платформы. Тик 1 секунда; сервисы проходят Ready → Running → Waiting, stop переводит в Stopped. Faulted зарезервирован для будущих сервисов. Это не замена планировщика FreeRTOS: один системный worker исполняет короткие операции; длительная работа должна получить отдельный адаптер/worker. API set_service/post/receive; FIFO ограничена 32 сообщениями, post возвращает false при переполнении. ISR не должен обращаться к этой очереди; необходим отдельный безопасный мост.

`firmware/platform` — абстракция времени, памяти, идентификации, вывода и reboot. Host использует steady_clock и stdin/stdout; его shell pump вызывается после входной строки (это тестовый CLI, не фоновый аналог .NET Simulator). Host reboot сбрасывает только часы. ESP32 использует esp_timer, heap, UART и системный restart. GPIO/storage следует добавлять отдельными интерфейсами по мере появления требований.

`firmware/shell` переводит команды в операции ядра. `firmware/protocol` определяет framing и Base64. ESP-IDF main связывает компоненты, читает UART и обслуживает watchdog. UART0 выделен под протокол, штатная консоль и runtime-логи отключены. Boot-ROM строки могут быть отброшены декодером как некорректные кадры.

Симулятор на C# и firmware на C++ имеют разные реализации; общий контракт документирован. .NET Simulator реализует больше команд (в частности logs) и синтетическую телеметрию. Общие сценарии проверяются тестами; полная автоматическая проверка паритета остаётся задачей следующей итерации.

Media пока представляет точку расширения: EVT media.ascii.open переключает экран. Следующий этап: локальный декодер на ПК, отменяемый цикл кадров, ограничение FPS, ASCII renderer и управление воспроизведением. ESP32 не декодирует видео.
