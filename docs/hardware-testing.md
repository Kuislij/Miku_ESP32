# Проверка ESP32 — отложена до появления платы

Реальные аппаратные проверки не выполнялись. ESP-IDF toolchain отсутствует; C++ host сборка проверяет только переносимый слой, а не ESP32-адаптер.

Когда плата появится:

1. Уточнить модель, питание, USB-UART или native USB, параметры flash и пины UART0.
2. Собрать ESP-IDF 5.x firmware с правильным target; проверить sdkconfig и подписку watchdog.
3. Прошить, открыть 115200/8N1 без DTR/RTS, убедиться в отсутствии смешения логов с протоколом.
4. Проверить ping/info/tasks/start/stop/video, частичные/слипшиеся/слишком длинные строки, восстановление после boot-лога.
5. Проверить heap под нагрузкой, отключение кабеля, повторное подключение и reboot (подтверждение до restart).
6. Проверить задержки UART, watchdog на зависшем сервисе, состояние системы при переполнении RX/FIFO и очереди IPC. Сейчас сообщения могут быть отброшены при заполнении IPC; нужна метрика потерь.
7. Длительный прогон телеметрии, контроль утечек и минимального свободного heap, проверка отсутствия зависаний UI.

API адаптера сверены с официальным [руководством UART ESP-IDF](https://docs.espressif.com/projects/esp-idf/en/v5.1/esp32/api-reference/peripherals/uart.html) и [описанием watchdog](https://github.com/espressif/esp-idf/blob/master/docs/en/api-reference/system/wdts.rst). Это не заменяет сборку для конкретной версии ESP-IDF и проверки на устройстве.
